# ДЗЕН МАШИНА v1 — контент-конвейер Sauna-Wood

```
inputs/ (Wordstat, идеи, конкуренты) ──► score ──► темы с баллом 0–100
                                                     │  ≥ 70
photos/ ──► photos (Claude описывает снимки)         ▼
kb/ (база знаний) ─────────────► generate: бриф → текст с фото → критик-эксперт ↻ доработка (до 2 раз) → 7 заголовков + лид
                                                     ▼
                                Telegram: ✅ Опубликовать · Заг. 1–7 · ✏️ На доработку (ответ = комментарий) · ❌
                                                     ▼
                                расписание → build → zen.xml → черновик в Студии Дзена → вы жмёте «Опубликовать»
                                                     ▼
                                inputs/stats.csv (1/3/7/30 день) → learn → data/insights.md → влияет на отбор тем
```

## Что где лежит
| Папка | Что это | Кто заполняет |
|---|---|---|
| `kb/company.md` | база знаний о компании | вы (можно постепенно) |
| `kb/cases/` | реальные объекты, по файлу на объект | вы |
| `kb/from_telegram.md` | факты, присланные боту командой `/fact` | бот |
| `kb/stopwords.txt` | штампы, которые ловятся автоматически | можно дополнять |
| `photos/` + `catalog.yaml` | фото объектов и их описания | вы кладёте фото, Claude описывает, вы проверяете |
| `inputs/wordstat/` | выгрузки Wordstat (CSV) | вы, раз в 1–2 недели |
| `inputs/ideas.txt`, `competitors.txt` | ваши идеи, заголовки конкурентов | вы / бот (`/idea`) |
| `inputs/stats.csv` | статистика из Студии Дзена | вы, бот напомнит |
| `prompts/` | все промпты агентов — правьте под себя | — |

## Пока базы знаний нет
Конвейер работает и без неё: статьи пишутся от лица эксперта отрасли, без «мы», «наши объекты» и
выдуманных случаев — это жёстко прописано в промптах и проверяется критиком.
Самый быстрый способ наполнить базу — отвечать боту: команда `/fact ...` и комментарии к черновикам
(«у нас трапы всегда отдельно от душа»). Через месяц такой работы статьи станут заметно сильнее.

## Запуск
Подробная пошаговая инструкция для начинающих — в отдельном документе. Кратко:
1. Публичный репозиторий на GitHub (на бесплатном тарифе Pages работает только для публичных), загрузите файлы.
2. Telegram: создайте бота у @BotFather, напишите ему, откройте
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` — число после `"chat":{"id":` и есть chat_id.
3. Settings → Secrets → Actions: `ANTHROPIC_API_KEY`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`.
4. Settings → Pages → Source: **GitHub Actions**.
5. `config.yaml`: `base_url`, `default_cover`, `cta_url` (сайт компании — ссылки получат UTM).
6. Положите фото в `photos/`, выгрузку Wordstat в `inputs/wordstat/`, запустите *Daily production*
   с галочкой «Пересобрать темы».
7. В Студии Дзена подключите RSS: `<base_url>/zen.xml`.

Локально то же самое: `pip install -r requirements.txt`, переменные окружения, `python pipeline.py -h`.

## Расписание (GitHub Actions)
- **Daily** 07:00 МСК: новые фото → (по понедельникам) отбор тем → 1 статья → в Telegram.
- **Telegram** каждые 30 мин днём: кнопки, комментарии, доработки. Бот отвечает с задержкой до 30 минут.
- **Publish** раз в 3 часа: сборка ленты.

Частота подобрана с запасом под бесплатный лимит приватного репозитория. В публичном репозитории
лимита на запуски нет — можно сделать Telegram чаще (строка cron в .github/workflows/telegram.yml).

## Команды бота
`/status` — черновики и расписание · `/fact текст` — факт в базу знаний · `/idea текст` — идея темы.
Ответ на сообщение со статьёй — комментарий для доработки.

## Важно
- **Фото**: публикуйте только объекты, где клиент не против. Claude помечает лица, документы и
  личные вещи (`privacy_flag`), но финальная проверка — ваша (`confirmed: true`).
- **Формат ленты**: требования Дзена меняются — при подключении сверьте категории в `config.yaml`
  со справкой. `publish_mode: draft` оставляет финальную кнопку за вами.
- **Модели**: критик работает на более сильной модели — это главная защита от технических ошибок.
  Одна статья — примерно 6–8 вызовов Claude.
